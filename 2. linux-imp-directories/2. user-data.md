# User & Variable Data Directories

Directories for user files, temporary data, and data that changes during normal system operation.

---

## /home (User Home Directories)

Personal directories for regular users. Each user gets their own subdirectory.

### Key Points

- One subdirectory per user (e.g., `/home/john`)
- Contains user's personal files, documents, settings
- User has full control of their own directory
- Often a separate partition (easier backups, reinstalls)
- Environment variable `$HOME` points here

### Structure

```
/home/
├── john/
│   ├── .bashrc             # Shell configuration
│   ├── .profile            # Login configuration
│   ├── .config/            # Application configs
│   ├── .local/             # User-specific data
│   ├── .ssh/               # SSH keys
│   ├── .cache/             # Application caches
│   ├── Desktop/
│   ├── Documents/
│   ├── Downloads/
│   ├── Music/
│   ├── Pictures/
│   └── Videos/
├── jane/
│   └── ...
└── guest/
    └── ...
```

### Important Hidden Files/Directories

| File/Directory | Purpose |
|----------------|---------|
| `.bashrc` | Bash shell configuration |
| `.profile` | Login shell configuration |
| `.bash_history` | Command history |
| `.ssh/` | SSH keys and config |
| `.config/` | Application settings (XDG) |
| `.local/share/` | Application data (XDG) |
| `.cache/` | Application caches |
| `.gnupg/` | GPG keys |
| `.vimrc` | Vim configuration |
| `.gitconfig` | Git configuration |

### Example

```bash
# Go to your home directory
$ cd ~
$ cd $HOME
$ cd

# View home directory
$ ls -la ~
drwxr-xr-x 15 john john 4096 Feb 14 10:00 .
drwxr-xr-x  5 root root 4096 Jan 01 00:00 ..
-rw-------  1 john john 5000 Feb 14 09:00 .bash_history
-rw-r--r--  1 john john  220 Jan 01 00:00 .bash_logout
-rw-r--r--  1 john john 3526 Jan 01 00:00 .bashrc
drwxr-xr-x  8 john john 4096 Feb 01 12:00 .config
drwxr-xr-x  2 john john 4096 Jan 15 10:00 Documents
drwxr-xr-x  2 john john 4096 Feb 10 14:00 Downloads
...

# Check your home directory
$ echo $HOME
/home/john

# View another user's home (if permitted)
$ ls /home/jane
```

### Permissions

```bash
# Typical home directory permissions
$ ls -la /home
drwxr-xr-x  3 root root 4096 Jan  1 00:00 .
drwxr-xr-x 19 root root 4096 Jan  1 00:00 ..
drwxr-x--- 15 john john 4096 Feb 14 10:00 john
drwxr-x--- 10 jane jane 4096 Feb 13 09:00 jane

# Make home private (only you can access)
$ chmod 700 ~

# Allow group to read
$ chmod 750 ~
```

## /root (Root User's Home)

The home directory for the **root** (administrator) user. Separate from `/home` for security.

### Key Points

- Home for the superuser (UID 0)
- NOT inside `/home` for security reasons
- Available even if `/home` fails to mount
- Contains root's personal config files
- Protected: only root can access

### Structure

```
/root/
├── .bashrc
├── .profile
├── .bash_history
├── .ssh/
└── (admin scripts, configs)
```

### Example

```bash
# Access root's home
$ sudo ls -la /root
drwx------  5 root root 4096 Feb 14 10:00 .
drwxr-xr-x 19 root root 4096 Jan  1 00:00 ..
-rw-------  1 root root 3000 Feb 14 09:00 .bash_history
-rw-r--r--  1 root root 3106 Jan  1 00:00 .bashrc
drwx------  2 root root 4096 Jan  1 00:00 .ssh
-rw-r--r--  1 root root  161 Jan  1 00:00 .profile

# Root's home in environment
$ sudo -i
# echo $HOME
/root
```

### Why Separate from /home?

1. **Boot reliability**: Available even if `/home` partition fails
2. **Security**: Different partition = different permissions
3. **Recovery**: Accessible in single-user/rescue mode
4. **Backups**: `/home` backups exclude admin files

## /tmp (Temporary Files)

Directory for **temporary files** that can be deleted at any time (usually on reboot).

### Key Points

- World-writable (anyone can create files)
- Usually cleared on reboot
- Sticky bit prevents users from deleting others' files
- May be mounted as tmpfs (RAM)
- Don't store important data here!

### Properties

```bash
$ ls -ld /tmp
drwxrwxrwt 15 root root 4096 Feb 14 10:00 /tmp
#        ^
#        └── Sticky bit (t) - only owner can delete their files
```

### Common Uses

- Temporary download files
- Build artifacts during compilation
- Session files
- Lock files
- Inter-process communication

### Example

```bash
# Create temp file
$ touch /tmp/myfile.txt

# Create temp file with mktemp (safer)
$ mktemp
/tmp/tmp.Xr3Kj2Lm

# Create temp directory
$ mktemp -d
/tmp/tmp.a1B2c3D4

# View temp files
$ ls /tmp
myfile.txt
systemd-private-xxx
tmp.Xr3Kj2Lm

# Check if tmpfs (RAM-based)
$ df -h /tmp
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           2.0G  100M  1.9G   5% /tmp
```

### Best Practices

```bash
# Use mktemp for unique names
TMPFILE=$(mktemp)
echo "data" > "$TMPFILE"
# ... use file ...
rm "$TMPFILE"

# Create with specific template
$ mktemp /tmp/myapp.XXXXXX
/tmp/myapp.a3Kj2m

# Use TMPDIR variable if set
$ echo ${TMPDIR:-/tmp}
/tmp
```

## /var (Variable Data)

Contains files that **change size and content** during normal operation: logs, mail, databases, caches.

### Key Points

- Data that grows and changes
- Logs, spool files, caches
- Often a separate partition (can fill up!)
- Some subdirectories are critical

### Structure

```
/var/
├── cache/          # Application cache data
├── lib/            # Variable state information
├── lock/           # Lock files (symlink to /run/lock)
├── log/            # Log files
├── mail/           # User mailboxes
├── opt/            # Variable data for /opt
├── run/            # Runtime data (symlink to /run)
├── spool/          # Spool for tasks waiting to be processed
├── tmp/            # Temporary files (preserved between reboots)
└── www/            # Web server files (common location)
```

### Important Subdirectories

#### /var/log (System Logs)

```bash
$ ls /var/log
alternatives.log   # Package alternatives
apt/               # APT package manager logs
auth.log           # Authentication log
boot.log           # Boot messages
cron.log           # Cron job logs
dmesg              # Kernel ring buffer
dpkg.log           # Package manager log
kern.log           # Kernel logs
mail.log           # Mail server logs
messages           # General system messages
mysql/             # MySQL logs
nginx/             # Nginx logs
syslog             # System log (main log)
wtmp               # Login records

# View system log
$ sudo tail -f /var/log/syslog

# View authentication log
$ sudo tail /var/log/auth.log

# View kernel messages
$ dmesg | tail
```

#### /var/cache (Cache Data)

```bash
$ ls /var/cache
apt/               # APT package cache
fontconfig/        # Font cache
man/               # Man page cache

# Clear APT cache
$ sudo apt clean
```

#### /var/lib (State Information)

```bash
$ ls /var/lib
apt/               # APT state
docker/            # Docker data
dpkg/              # Package manager state
mysql/             # MySQL databases
postgresql/        # PostgreSQL databases
systemd/           # systemd state
```

#### /var/spool (Spool Directories)

```bash
$ ls /var/spool
anacron/           # Anacron job spool
cron/              # Cron spool
cups/              # Print jobs
mail/              # Incoming mail
```

### Example

```bash
# Check log sizes
$ du -sh /var/log/*
50M     /var/log/syslog
20M     /var/log/auth.log
100M    /var/log/journal
...

# Find large files in /var
$ sudo find /var -size +100M

# Check /var partition usage
$ df -h /var
```

### Log Management

```bash
# View logs with journalctl (systemd)
$ journalctl -f                    # Follow logs
$ journalctl -u nginx              # Service logs
$ journalctl --since "1 hour ago"  # Recent logs

# Rotate logs manually
$ sudo logrotate -f /etc/logrotate.conf
```

## /srv (Service Data)

Data served by this system. Contains data for services like web servers, FTP servers, etc.

### Key Points

- Site-specific data served by system
- Web server files, FTP files, etc.
- May be empty on desktop systems
- Separates service data from system data

### Structure

```
/srv/
├── ftp/            # FTP server files
├── http/           # HTTP/web server files
├── www/            # Alternative web server location
└── git/            # Git repositories
```

### Example

```bash
# Common web server setups
/srv/www/                    # Web files
/srv/www/example.com/        # Virtual host
/srv/www/example.com/public_html/

# FTP server
/srv/ftp/                    # FTP root
/srv/ftp/pub/                # Public downloads

# Check contents
$ ls -la /srv
total 12
drwxr-xr-x  3 root root 4096 Jan  1 00:00 .
drwxr-xr-x 19 root root 4096 Jan  1 00:00 ..
drwxr-xr-x  2 root root 4096 Jan  1 00:00 ftp
```

### /srv vs /var/www

| Location | Common Use |
|----------|------------|
| `/srv/www` | FHS recommended for web content |
| `/var/www` | Debian/Ubuntu default for Apache |

Both are valid; distributions differ in preference.

---

> **Pro Tip:** Put `/home` and `/var` on separate partitions. This prevents a full `/var/log` from crashing your system, and makes backups easier.
