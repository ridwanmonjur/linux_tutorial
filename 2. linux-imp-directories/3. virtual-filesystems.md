# Virtual Filesystems

These directories don't contain real files on disk. They're **virtual filesystems** generated by the kernel, providing interfaces to system information and devices.

---

## /dev (Device Files)

Contains **device files** that represent hardware and virtual devices. Everything in Linux is a file—including devices!

### Key Points

- Managed by `udev` (device manager)
- Created dynamically when devices are detected
- Not stored on disk (devtmpfs filesystem)
- Access hardware through file operations

### Types of Device Files

| Type | Symbol | Description |
|------|--------|-------------|
| Block | `b` | Random access, fixed blocks (disks) |
| Character | `c` | Sequential access, byte stream (keyboards, serial) |

### Important Devices

#### Storage Devices

| Device | Description |
|--------|-------------|
| `/dev/sda` | First SATA/SCSI disk |
| `/dev/sda1` | First partition of first disk |
| `/dev/sdb` | Second disk |
| `/dev/nvme0n1` | First NVMe SSD |
| `/dev/nvme0n1p1` | First partition of NVMe |
| `/dev/mmcblk0` | SD card / eMMC |
| `/dev/sr0` | CD/DVD drive |
| `/dev/loop0` | Loop device (mount images) |

#### Virtual/Special Devices

| Device | Description |
|--------|-------------|
| `/dev/null` | Black hole - discards all input |
| `/dev/zero` | Infinite source of zero bytes |
| `/dev/random` | Random data (blocks when entropy low) |
| `/dev/urandom` | Random data (non-blocking) |
| `/dev/full` | Always returns "disk full" error |
| `/dev/tty` | Current terminal |
| `/dev/console` | System console |
| `/dev/stdin` | Standard input (link to fd/0) |
| `/dev/stdout` | Standard output (link to fd/1) |
| `/dev/stderr` | Standard error (link to fd/2) |

### Example

```bash
# List devices
$ ls -l /dev | head -20
crw-rw-rw-  1 root root    1,  3 Feb 14 08:00 null
crw-rw-rw-  1 root root    1,  5 Feb 14 08:00 zero
crw-rw-rw-  1 root root    1,  8 Feb 14 08:00 random
crw-rw-rw-  1 root root    1,  9 Feb 14 08:00 urandom
brw-rw----  1 root disk    8,  0 Feb 14 08:00 sda
brw-rw----  1 root disk    8,  1 Feb 14 08:00 sda1
crw--w----  1 root tty     4,  0 Feb 14 08:00 tty0

# Discard output
$ echo "ignored" > /dev/null

# Generate random bytes
$ head -c 32 /dev/urandom | xxd

# Create file full of zeros
$ dd if=/dev/zero of=zeros.bin bs=1M count=10

# Check disk devices
$ lsblk
NAME   MAJ:MIN RM   SIZE RO TYPE MOUNTPOINT
sda      8:0    0   500G  0 disk
├─sda1   8:1    0   512M  0 part /boot
├─sda2   8:2    0    50G  0 part /
└─sda3   8:3    0   449G  0 part /home
```

### Common Operations

```bash
# Write directly to disk (DANGEROUS!)
$ sudo dd if=image.iso of=/dev/sdb bs=4M

# Create loop device from file
$ sudo losetup /dev/loop0 disk.img

# Check device info
$ sudo fdisk -l /dev/sda

# Find device for mount point
$ df /home
```

## /proc (Process Information)

A **virtual filesystem** that provides information about processes and the kernel. Numbers are process IDs (PIDs).

### Key Points

- Virtual - files generated on-the-fly by kernel
- No disk space used
- Read process and system information
- Some files are writable (kernel tuning)
- Numbers represent process IDs

### Structure

```
/proc/
├── 1/                  # Process with PID 1 (init/systemd)
├── 2/
├── .../
├── [pid]/              # Info about process [pid]
│   ├── cmdline         # Command line arguments
│   ├── cwd             # Current working directory (link)
│   ├── environ         # Environment variables
│   ├── exe             # Executable (link)
│   ├── fd/             # File descriptors
│   ├── maps            # Memory maps
│   ├── status          # Process status
│   └── ...
├── cpuinfo             # CPU information
├── meminfo             # Memory information
├── version             # Kernel version
├── uptime              # System uptime
├── loadavg             # Load average
├── mounts              # Mounted filesystems
├── partitions          # Partition information
├── filesystems         # Supported filesystems
├── sys/                # Kernel tunables
└── net/                # Network information
```

### System Information Files

| File | Content |
|------|---------|
| `/proc/cpuinfo` | CPU details |
| `/proc/meminfo` | Memory statistics |
| `/proc/version` | Kernel version |
| `/proc/uptime` | Uptime in seconds |
| `/proc/loadavg` | Load average |
| `/proc/mounts` | Mounted filesystems |
| `/proc/partitions` | Partition table |
| `/proc/cmdline` | Kernel boot parameters |
| `/proc/filesystems` | Supported filesystems |
| `/proc/interrupts` | IRQ statistics |

### Example

```bash
# View CPU info
$ cat /proc/cpuinfo
processor   : 0
vendor_id   : GenuineIntel
model name  : Intel(R) Core(TM) i7-9700K
cpu MHz     : 3600.000
cache size  : 12288 KB
...

# View memory info
$ cat /proc/meminfo
MemTotal:       16384000 kB
MemFree:         8000000 kB
MemAvailable:   12000000 kB
Buffers:          500000 kB
Cached:          3500000 kB
...

# Check kernel version
$ cat /proc/version
Linux version 5.15.0-generic (buildd@host) ...

# System uptime
$ cat /proc/uptime
86400.50 172800.25
# First number: uptime in seconds
# Second number: idle time in seconds

# Load average
$ cat /proc/loadavg
0.50 0.75 0.80 1/250 12345
# 1min, 5min, 15min averages, running/total processes, last PID
```

### Process Information

```bash
# View your shell process
$ cat /proc/$$/status
Name:   bash
State:  S (sleeping)
Pid:    12345
PPid:   12344
Uid:    1000    1000    1000    1000
...

# View command line of a process
$ cat /proc/1/cmdline
/sbin/init

# View environment of a process
$ sudo cat /proc/1/environ | tr '\0' '\n'

# List open file descriptors
$ ls -l /proc/$$/fd
lrwx------ 1 user user 0 Feb 14 10:00 0 -> /dev/pts/0
lrwx------ 1 user user 0 Feb 14 10:00 1 -> /dev/pts/0
lrwx------ 1 user user 0 Feb 14 10:00 2 -> /dev/pts/0

# View current working directory of process
$ readlink /proc/$$/cwd
/home/user

# See what executable is running
$ readlink /proc/$$/exe
/usr/bin/bash
```

### Kernel Tuning (/proc/sys)

```bash
# View/modify kernel parameters
$ cat /proc/sys/net/ipv4/ip_forward
0

# Enable IP forwarding (temporarily)
$ echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# View all parameters with sysctl
$ sysctl -a | head
```

## /sys (Sysfs - System Information)

A **virtual filesystem** exposing kernel objects: devices, drivers, and other kernel subsystems.

### Key Points

- Provides structured view of devices and drivers
- More organized than /proc for hardware
- Used by udev for device management
- Allows hardware configuration

### Structure

```
/sys/
├── block/              # Block devices
├── bus/                # Bus types (usb, pci, etc.)
├── class/              # Device classes
│   ├── backlight/      # Screen brightness
│   ├── net/            # Network interfaces
│   ├── power_supply/   # Battery, AC adapter
│   └── thermal/        # Temperature sensors
├── devices/            # All devices (hierarchical)
├── firmware/           # Firmware interfaces
├── fs/                 # Filesystem information
├── kernel/             # Kernel settings
├── module/             # Loaded kernel modules
└── power/              # Power management
```

### Common Uses

```bash
# View block devices
$ ls /sys/block
sda  sdb  nvme0n1

# Get disk size (in 512-byte sectors)
$ cat /sys/block/sda/size
1000000000

# View network interfaces
$ ls /sys/class/net
eth0  lo  wlan0

# Check network link state
$ cat /sys/class/net/eth0/operstate
up

# Get MAC address
$ cat /sys/class/net/eth0/address
00:11:22:33:44:55

# Adjust screen brightness
$ cat /sys/class/backlight/*/brightness
100
$ echo 50 | sudo tee /sys/class/backlight/*/brightness

# Check battery status
$ cat /sys/class/power_supply/BAT0/status
Discharging
$ cat /sys/class/power_supply/BAT0/capacity
75

# Read CPU temperature
$ cat /sys/class/thermal/thermal_zone0/temp
45000
# Value in millidegrees Celsius (45.0°C)

# View USB devices
$ ls /sys/bus/usb/devices/

# Check if laptop lid is open
$ cat /sys/class/input/*/device/lid_state
open
```

### Device Information

```bash
# View device tree
$ ls /sys/devices/
pci0000:00  platform  system  virtual  ...

# Find device by driver
$ ls /sys/module/nvidia/drivers/

# View module parameters
$ ls /sys/module/usb_storage/parameters/

# Check device power state
$ cat /sys/devices/.../power/runtime_status
```

## /run (Runtime Data)

Contains **runtime data** since boot. Replaces older `/var/run` and `/var/lock`.

### Key Points

- tmpfs (RAM-based) - cleared on reboot
- Process IDs, sockets, lock files
- Created fresh each boot
- `/var/run` is typically a symlink to `/run`

### Structure

```
/run/
├── lock/               # Lock files
├── log/                # Runtime logs (journal)
├── mount/              # Mount information
├── shm/                # Shared memory
├── systemd/            # systemd runtime data
├── user/               # Per-user runtime dirs
│   └── 1000/           # User UID 1000
├── utmp                # Login records
├── docker.sock         # Docker socket
├── sshd.pid            # SSH daemon PID
└── *.pid               # Various PID files
```

### Example

```bash
# View runtime files
$ ls /run
docker.sock  lock  log  mount  shm  systemd  user  utmp  ...

# Check PID files
$ cat /run/sshd.pid
1234

# View systemd runtime
$ ls /run/systemd
journal  notify  private  ...

# User runtime directory
$ ls /run/user/$(id -u)
bus  dconf  gnupg  systemd  ...

# Check /var/run is symlink
$ ls -la /var/run
lrwxrwxrwx 1 root root 4 Jan 1 00:00 /var/run -> /run
```

### Common Files

| File | Purpose |
|------|---------|
| `/run/*.pid` | Process ID files for services |
| `/run/*.sock` | Unix sockets |
| `/run/lock/*` | Lock files |
| `/run/utmp` | Current login records |
| `/run/user/$UID/` | Per-user runtime directory |

---

## Comparison

| Directory | Content Type | Persistence | Access |
|-----------|--------------|-------------|--------|
| `/dev` | Device files | Dynamic | Direct HW access |
| `/proc` | Process/kernel info | Virtual | Read (some write) |
| `/sys` | Device/driver info | Virtual | Read (some write) |
| `/run` | Runtime data | Cleared on boot | PID, sockets, locks |

---

> **Pro Tip:** Use `/proc` and `/sys` for scripts that need system information without calling external commands. It's often faster and more reliable.
